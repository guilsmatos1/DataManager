## MEDIUM Severity

### 4. Duplicate Cache State
**What**: Both `ingestion/cache.py` and `ingestion/tcp_server.py` maintain in-memory deal cache state. Responsibility is split.
**Risk**: Cache coherence issues; unclear ownership makes maintenance harder.

### 5. Stale Documentation
**What**: `projects/datamanager/CLAUDE.md` (and related docs) describe an old Parquet/SQLite storage layout. The component has migrated to SQLAlchemy + PostgreSQL.
**Risk**: Misleading documentation causes onboarding confusion and incorrect assumptions about data flow.

### 6. Per-Call DB Sessions in Repository
**What**: Some repository methods create new DB sessions per call rather than using an injected session.
**Risk**: Transaction isolation issues; harder to test; potential connection pool exhaustion under load.

### 7. Brute-Force Optimization Memory Ceiling
**What**: `components/portifoliomaster/services/optimization.py` uses brute-force portfolio optimization that loads all combinations into memory.
**Risk**: With many strategies, memory usage grows combinatorially. No streaming/chunking approach implemented.

### 8. `while True` Polling Loops
**What**: Some ingestion/monitoring code uses `while True` polling instead of event-driven patterns.
**Risk**: CPU waste, harder to test, no backpressure mechanism.

### 9. Fragile SQLite Test Shims
**What**: `conftest.py` applies monkey-patches to SQLAlchemy's SQLite DDL compiler to handle PostgreSQL-specific types (JSONB, BigInteger autoincrement).
**Risk**: Shims may hide real PostgreSQL-specific bugs. Tests pass on SQLite but could fail on real PG for subtle type-handling reasons. Shims break if SQLAlchemy internals change.

## LOW Severity

### 10. Consistent `portifolio` Typo
**What**: The misspelling `portifolio` (should be `portfolio`) is embedded throughout:
- Directory names: `bases/portifolio_master_cli/`, `components/portifoliomaster/`
- Package names: `trademachine.portifoliomaster`, `trademachine.portifolio_master_cli`
- CLI entry points, import paths, test files
**Impact**: Cosmetic but pervasive. Fixing requires a coordinated rename across the entire codebase. Low priority given it's a personal project.

### 11. MD5 Used for Deduplication
**What**: MD5 hashing used in data deduplication logic (datamanager storage).
**Risk**: MD5 is cryptographically broken. For dedup-only (non-security) use, this is acceptable but non-standard. Could cause hash collisions on adversarial input (non-issue for OHLCV data).

### 12. `0.0.0.0` Default Binding
**What**: TCP server and API server default to binding `0.0.0.0` (all interfaces).
**Risk**: Acceptable for a personal/local deployment, but exposes services on all network interfaces by default. No TLS on TCP ingestion channel.

### 13. Missing Test Coverage in Key Areas
**What**:
- `bases/` — Only minimal smoke tests; no CLI interaction tests
- `components/backtestengine/` — No meaningful tests (empty component)
- DataManager fetchers — `test_fetchers.py` is new and likely incomplete
- MT5 parser — Light coverage
**Impact**: Regressions in these areas may go undetected.

### 14. In-Memory Rate Limiting Only
**What**: `slowapi` rate limiter is in-memory only (no Redis backend).
**Impact**: By design for single-worker personal use. Would need Redis if ever scaled horizontally. Documented in CLAUDE.md as an intentional tradeoff.
